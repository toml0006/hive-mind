# Governance

Hive Mind uses a maintainer-led, contribution-friendly governance model while
the project is young.

## Roles

- Contributors submit issues, reviews, documentation, code, and other project
  improvements.
- Maintainers triage work, review changes, manage releases, enforce community
  policies, and protect the project's architectural and privacy invariants.

Consistent contributors may be invited to become maintainers based on sustained
technical judgment, review quality, reliability, and community conduct.

## Decisions

Routine changes are decided through pull-request review. Significant changes
to storage semantics, scope isolation, compatibility, security, or governance
should begin with a public design issue and remain open long enough for
meaningful feedback.

Maintainers seek rough consensus. When consensus is not available, maintainers
make and document the decision, prioritizing data safety, project isolation,
backward compatibility, and the canonical/semantic boundary.

## Releases

Maintainers may release any change merged to the default branch after required
checks pass. Breaking changes require release notes and, after the project
leaves alpha, a documented deprecation path when practical.

## Changes to governance

Governance changes use the same public pull-request process and require approval
from a majority of active maintainers.
